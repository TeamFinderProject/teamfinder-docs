# Запуск и демонстрация TeamFinder

## Полный запуск через Docker

Нужны Git, Docker и Docker Compose. На Windows сначала запустите Docker Desktop.

```text
teamfinder/
  teamfinder-backend/
  teamfinder-frontend/
```

```bash
git clone https://github.com/TeamFinderProject/teamfinder-backend.git
git clone https://github.com/TeamFinderProject/teamfinder-frontend.git
cd teamfinder-backend
docker compose up -d --build
docker compose ps
```

Репозитории клонируются с основной веткой develop. Compose находится в backend и собирает frontend из соседней папки. Порты 5432, 8080 и 8081 должны быть свободны.

| Адрес | Что открыть |
|---|---|
| http://localhost:8081 | Сайт |
| http://localhost:8080/swagger | Swagger: контракт и реализация |
| http://localhost:8080/health | Проверка доступности API |

Миграции применяются при старте API. Обычный запуск не требует пересоздания миграций или удаления базы. Данные PostgreSQL сохраняются в Docker volume.

Остановить: `docker compose stop`. Запустить снова: `docker compose up -d`. Посмотреть ошибки: `docker compose logs --tail 100 api`. Не используйте `down -v` для обычной остановки: команда удаляет данные.

## Демо-аккаунты

При DEMO_SEED=true backend добавляет начальные данные, если демо-пользователь ещё не существует. Пароль аккаунтов ниже: `Demo12345!`.

| Email | Начальная роль |
|---|---|
| ivan@demo.local | Владелец TeamFinder |
| petr@demo.local | Кандидат с ожидающей заявкой на Backend |
| anna@demo.local | Участник TeamFinder на Frontend |
| maria@demo.local | Владелец хакатона и проекта в работе |

После демонстрационных действий статусы сохраняются: повторный запуск не возвращает принятую заявку в Pending. Для повторного показа создайте нового пользователя и новую заявку.

## Что показать

1. Зарегистрировать нового пользователя, заполнить профиль и навыки, сохранить и обновить страницу.
2. Открыть каталог, проверить фильтр, проект и объяснение matching роли.
3. Подать заявку на свободную роль; проверить Pending и отсутствие занятого места до принятия.
4. В другом сеансе войти владельцем. Принять заявку, открыть команду и проверить увеличение занятого места.
5. Создать отдельный проект с ролью, capacity и навыками одной формой. Проверить появление в «Моих проектах»; при открытом наборе — в каталоге другого пользователя.
6. Проверить отзыв другой Pending-заявки, уведомления и допустимые переходы проекта на отдельном тестовом проекте.
7. В Swagger выполнить GET /api/skills: проверить HTTP 200 и JSON. Защищённым запросам нужен access token через Authorize.

Для разных пользователей используйте обычное окно и инкогнито либо разные профили браузера. «Мои проекты» зависит от текущего пользователя; черновик виден только владельцу.

## Telegram

Скопируйте .env.example в .env в папке backend. Задайте TELEGRAM_BOT_TOKEN и TELEGRAM_BOT_USERNAME без @. После изменения выполните `docker compose up -d --force-recreate api`. Токен хранится локально и не включается в коммиты.

Профиль → «Подключить Telegram» → перейти по ссылке → Start. Затем создайте событие для привязанного пользователя и отдельно проверьте доставку сообщения. Статус «подключено» подтверждает привязку, но сам по себе не доказывает доставку. Один токен должен обслуживаться одним запущенным backend.

## Фиксация результатов

В [задаче проверки UC](https://github.com/TeamFinderProject/teamfinder-docs/issues/18) фиксируйте для каждого сценария: commit backend/frontend, действие, ожидаемый и фактический результат, дату и ошибку либо ссылку на Issue. Пустая отметка не означает ни успешный тест, ни неисправность. Проверки API в CI и ручной показ интерфейса учитываются отдельно.
