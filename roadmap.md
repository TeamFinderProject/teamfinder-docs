# TeamFinder — Roadmap

Обновлено 01.11.2026 после защиты checkpoint 3. Основная ветка — `develop`; задачи и текущие исполнители находятся на [Kanban](https://github.com/orgs/TeamFinderProject/projects/1).

## Этапы

| Этап | Объём | Состояние |
|---|---|---|
| Начало проекта | Тема, репозитории, распределение ролей | Материалы сохранены в репозиториях |
| Подготовка MVP | Требования, сценарии, макеты, ERD, архитектура, контракт API | Документы и исходники находятся в develop |
| Checkpoint 3 / лабораторная 3 | Вход, профиль, проекты и роли, matching, заявки, Membership, уведомления; запуск через Docker | Защищён. Backend PR #13 слит 01.11.2026; frontend и документы также находятся в develop |
| После checkpoint 3 | Зафиксировать замечания преподавателя, согласовать исправления и повторные проверки | Следующий этап; подробные замечания ещё предстоит внести |
| Финальная защита | Стабильная версия, документация, воспроизводимый показ, согласованные улучшения | Ожидается в декабре 2026; точная дата уточняется |

«Checkpoint 2 / ЛР 3» в названиях старых Issues означает второй checkpoint по заданию, соответствующий лабораторной 3. В обсуждениях команды он называется checkpoint 3.

## Ближайшая работа

1. Зафиксировать замечания защиты в Issues: проблема, ожидаемое поведение, ответственный и способ проверки.
2. Привести README, инструкции запуска и текущий состав команды к фактическому состоянию репозиториев.
3. По [demo-guide.md](demo-guide.md) повторить основной путь и записать результаты по UC. Слияние PR и защита сами по себе не подтверждают каждый сценарий.
4. Исправлять замечания отдельными PR с review второго участника и обязательным CI.
5. После стабилизации подготовить выпуск: согласованный PR из develop в main и тег. До публикации не называть ветку опубликованным релизом.

## Кандидаты на дальнейшее развитие

Email, web push, восстановление пароля и настройки каналов уведомлений обсуждались как развитие проекта. Это предложения, а не подтверждённые функции или обязательства ближайшего этапа. Объём и сроки согласуются после разбора замечаний преподавателя.

Приоритет остаётся у основного сценария: регистрация → профиль → каталог → роль и matching → заявка → решение владельца → Membership и команда. Встроенный чат не входит в v1; дополнительные сервисы и инфраструктура требуют отдельной причины.

## Проверка перед выпуском

| Проверка | Подтверждение |
|---|---|
| Backend | Сборка, соответствие миграций модели, применение миграций, интеграционные тесты в Backend CI |
| Frontend | Установка по lock-файлу, production build и Docker build в frontend-ci |
| Интеграция | Запуск backend + frontend + PostgreSQL на чистом окружении; запись commit и фактических результатов |
| Сценарии | Проверка UC с результатами и Issues на найденные ошибки |
| Документы | Рабочие ссылки, согласованность UI, OpenAPI и реализации |
| Публикация | Review, merge в целевую ветку, проверка версии и инструкции запуска |
